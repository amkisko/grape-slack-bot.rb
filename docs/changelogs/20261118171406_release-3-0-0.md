# Release 3.0.0

## Participants

Andrei Makarov (@amkisko)

## Decisions

- Prepare 3.0.0 with the opt-in Slack Schema API and the classic Slack HTTP
  interaction routes described in RFC-0002.
- Keep the version in the library, the root lockfile, and all four Appraisal
  lockfiles aligned. The lockfile diff from 2.1.3 contains only the project gem
  version.
- Extract the GitHub release text with the same changelog helper that
  `make release` uses.

## Effects

- `CHANGELOG.md` contains the 3.0.0 section dated 2026-11-18.
- `gem build grape-slack-bot.gemspec --output tmp/release/3.0.0/grape-slack-bot-3.0.0.gem`
  built a 35328-byte package with 39 files. `Gem::Package#verify` passed.
  The extracted package loaded version 3.0.0 and ran a registered Schema
  shortcut. `shasum -a 256 -c SHA256SUMS` passed in `tmp/release/3.0.0`.
- `BUNDLE_FROZEN=1 POLYRUN_COVERAGE=1 make test` passed with a writable
  `RUBOCOP_CACHE_ROOT`. RuboCop checked 77 files and all five test shards
  passed. RBS emitted the existing Ruby 4.1 `tsort` warning.
- `BUNDLE_FROZEN=1 BUNDLE_GEMFILE="gemfiles/$appraisal.gemfile" bundle exec rspec --format progress`
  returned 420 examples and zero failures per run. MRI 3.4.11 ran the
  `rails72` and `rails8ruby34` appraisals with locked gems installed from the
  local cache. MRI 4.0.2 ran all four appraisals, including the lockfile
  named `rails8truffleruby`. The TruffleRuby runtime check remains open.
- `git diff --check` passed.

## Next

- Use the clean-tree release workflow to publish the gem, tag 3.0.0, and
  create the GitHub release.
